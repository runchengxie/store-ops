# Source-backed eMAG operational assistance

Approved user scope: connect the private training library to runtime retrieval; deepen existing-product guidance and local upload checks; gate promotion scenarios on explicit cost evidence. Preserve the compact homepage and put details on a secondary page. Analytics ingestion, settlement reconciliation, remote listing submission and new merchant writers are later work.

## Design

1. An owner CLI imports an offline library JSON into a private, revisioned local SQLite index under `settings.data_dir`. Store source title, provenance, source hash, declared date/unknown date, original locator, excerpts, trust class and conflict notes. No originals, personal paths, sharing tokens or real training excerpts enter Git. Import is atomic and bounded; a malformed pack preserves the current index. Source content remains untrusted data, never executable instructions.
2. Deterministic local search supports Chinese two-character queries, English, punctuation and literal wildcard characters. Return bounded excerpts with source/locator/hash/revision and historical/machine-transcription labels, including related conflict notes. A source-detail read returns references and excerpts, not arbitrary file paths or an open filesystem reader. Admin HTTP and a scoped read-only MCP tool expose the same service; shared generic knowledge search remains intact.
3. A snapshot-bound decision-support read ranks existing-stock blockers and identifies missing evidence. It explains observed platform fields and further checks rather than asserting an unproven root cause. No external network, market sales inference, LLM call or automatic store operation occurs.
4. Local XLSX preflight reads uploaded bytes in memory with ZIP/XML limits. It uses actual template field headers and declared required fields; flags guidance-only files, template rows, missing values, duplicate identities, formulas needing evaluation and inconsistent family metadata. Unknown layouts and ambiguous checks stay unsupported/review, never platform-approved. No macros, external requests, file extraction to arbitrary paths, recalculation or upload to eMAG.
5. A per-product promotion check reuses saved procurement inputs and Decimal commerce calculations. Current snapshot/product identity is mandatory. Missing/stale cost records and unconfirmed extra per-unit costs return incomplete. Show discount and voucher scenarios separately; sequential stacking only when explicitly assumed. Commission reductions are relative reductions of the entered fee rate, not percentage points; support subsidies are separate assumptions. Show before-subsidy and assumed-support results separately. Never call an estimate actual profit or a platform eligibility approval; historical rates and campaign thresholds are not defaults.
6. A bilingual admin-only secondary `/insights` page contains knowledge search, bounded store suggestions, upload preflight and promotion checks. Reveal explanations/citations on demand. Preserve store-switch/request race handling, server errors, unknown states and mobile layout. No private API calls for non-admin users. Add only a secondary navigation entry, no new homepage panels.

## API contracts

- `GET /api/emag/knowledge/status` -> `{available, revision, source_count, chunk_count}`.
- `GET /api/emag/knowledge/search?q=&limit=5` -> `{available, revision, results:[{source_id,chunk_id,title,locator,excerpt,trust,date,source_hash,conflicts:[]}], marketplace_writes:false}`. Query length 1..500, limit 1..20.
- `GET /api/emag/knowledge/sources/{source_id}` -> `{source_id,title,source_hash,trust,date,revision,conflicts:[],chunks:[{chunk_id,locator,excerpt}],truncated}`; bounded, no private paths.
- `GET /api/emag/stores/{store_id}/decision-support` -> `{store_id,snapshot_id,captured_at,products:[{id,name}],cards:[{id,product_id,title_key,reason,priority,stock,evidence:[{field,value}],checks:[{key,status}],knowledge_query}],marketplace_writes:false}`. At most 100 cards, observed stock prioritized, unknown stock retained.
- `POST /api/emag/stores/{store_id}/preflight` multipart fields `snapshot_id` and `file` (.xlsx; max 5 MiB). -> `{store_id,snapshot_id,file_name,status,layout:{sheet,header_row,data_start_row,fields:[]},row_count,issues:[{code,severity,sheet,row,column,field,details}],truncated,knowledge_query,marketplace_writes:false}`. Status `needs_review|unsupported`; no platform-ready attestation. Max 200 issues, 1000 product rows, ZIP expanded max 64 MiB/500 entries; no path traversal, DTD or unsupported active content.
- `POST /api/emag/stores/{store_id}/promotion-check/{product_id}` JSON `{snapshot_id,discount_pct:"0",voucher_pct:"0",stacking:"unknown"|"sequential",commission_reduction_pct:"0",support_ex_vat_ron:null,extra_cost_ron:null}` -> `{store_id,snapshot_id,product_id,status:"incomplete"|"review_required",price_basis:"exclusive_vat",currency:"RON",cost_revision,missing:[],warnings:[{code,details}],scenarios:[{kind,sale_price_ex_vat_ron,economics,support_ex_vat_ron,contribution_with_assumed_support_ron}],knowledge_query,marketplace_writes:false}`. All numeric inputs bounded strings, percentages 0..100. `extra_cost_ron` must be explicit (0 is allowed); rates and support require independent verification. Do not use a stale cost record as complete current evidence.

All routes require administrator identity; eMAG HTTP routes use `/api/emag` registration. Unknown stores/products are 404, stale snapshots 409, bad inputs 422/400, oversized uploads 413. Responses carry stable language-neutral codes; UI text is in locale catalogs. Shared infrastructure remains generic with only the eMAG adapter enabled.
