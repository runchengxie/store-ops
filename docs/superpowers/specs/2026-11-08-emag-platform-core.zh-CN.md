# store-ops：通用底座与唯一 eMAG adapter

用户已明确的边界：产品保留通用功能层，目前只有 eMAG adapter；不保留 Amazon 的可执行实现、算法、技能和产品内容。未来平台通过新增 adapter 接入，店铺是账号/市场配置，不为每家店单独建 adapter。

## 推荐实施方案
采用最小接口抽取，而非先建立覆盖所有平台的 ERP 数据模型。先把当前首页、店铺选择、证据读取和能力分发接到通用接口，再完整移除 Amazon 执行入口及专属实现。

## 分层与接口
1. 通用底座：登录/RBAC、AI与会话、MCP传输及令牌、任务调度基础设施、审批与审计、证据存储/修订、通用报告和图片工具、状态首页。
2. 平台注册表：仅注册 `emag`。声明 adapter版本和能力，区分“已支持/不支持/尚未核实”，并把运行是否已配置、可用、资料完整与能力支持分开。
3. eMAG adapter：复用现有采集、业务资料、状态解释、成本规则、Listing、广告复核、库存清理和单商品受控改价。保留 eMAG 特有扩展及原始字段，避免假装 PNK/平台状态是通用规则。
4. 最小通用端口：店铺列表、资料概况、采集健康、按能力读取证据。首页只消费带来源/时间/版本的概况，消除直接 `/emag/...` 依赖。特有工作流继续通过 eMAG 扩展接口提供，不为改名迁移全部文件。
5. 通用层控制用户权限、能力白名单、审批范围、快照/修订绑定与审计；adapter控制凭据绑定、允许调用的平台接口和平台验证。读写按接口语义区分，不能把HTTP POST一律当写操作。不新增通用自动写接口。

## Amazon 完整下线范围
- 删除旧前端页面、路由、API客户端、导航、专属图表与算法。
- 删除 Amazon/ASIN 广告审计、市场与选品、Listing抓取、新闻、Lingxing/cockpit等后端路由、服务和启动任务；删除其MCP工具定义及处理器。
- 删除 `skills/amazon`、SellerSprite工具桥、Amazon专属提示词与当前产品文档。
- 停止启动时注册Amazon技能和Sorftime/SIF/SellerSprite等集成。对应用自己管理的能力做白名单，不重写用户外部MCP配置。
- 清理看似通用但实际依赖ASIN/BSR的自定义数据源契约；确有eMAG消费者的报告、图像和数学基础设施保留。
- 不保留“禁用但仍能执行”的Amazon adapter或legacy隐藏开关。旧API/页面按普通404下线；不维护新的兼容别名。

## 保留与迁移
保留已有店铺ID、快照、数据库、凭证、私有配置和计划任务契约；只停止代码中的Amazon执行，不自动删除用户历史数据。既有eMAG CLI和配置键可作为兼容入口委托给新分发层，保证笔记本巡检不因命名迁移中断。上游许可、事实性历史ADR和更新记录保留并标明历史。外部安装的独立Agent发行包不在本仓库删除范围，但store-ops不再默认注册或提供Amazon能力。

已有通用Agent任务若明确引用本应用已退休Amazon技能/工具，保留原任务和历史内容，在分发前失败关闭并显示“能力已下线”；不通过简单关键词猜测任意自由文本意图。用户自有外部Agent能力不属于“本仓库移除Amazon实现”的保证范围，不为此重写外部私有配置。

## 验证和交付
新任务分支从首页PR合并结果建立，独立PR交付。验证registry只有eMAG、未知平台/能力失败关闭、旧Amazon路由/MCP/启动任务消失、升级不修改用户私有数据、eMAG端到端操作与现有认证/审批契约仍有效。运行完整后端套件、Ruff、前端类型/语言/构建、文档检查、真实App路由验证，再独立审阅、CI、合并并更新笔记本服务。

## 上游更新处理
本轮核查的上游10个提交不整包合并：主要通用可靠性修复已在本fork移植，Amazon修复不再引入。错误favicon和保留对话页的移动端标题可在小型独立修复中按实际复现移植，不把上游大型仪表盘样式带入新首页。
