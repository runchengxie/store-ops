# Go 长期值守管家：首版设计

目标：同一台笔记本长期管理多个只读巡检任务，断网或重启后保留任务记录；可暂停，避免重复采集。保留 Python 检查与分析、TypeScript 页面。

## 方案与取舍

1. Python 继续承担全部调度：改动最少，现有 SQLite 防重与暂停可复用。
2. Go 独立任务管家 + Python 工作进程（推荐、用户已同意推进方向）：部署独立、职责清楚；代价是两种语言及进程协议维护。
3. 全部改写 Go：可行，但表格、知识库、分析、API 和现有测试迁移量大，首版不采用。

Rust、C/C++ 的低层性能和内存控制不是当前瓶颈；Rust 编译期安全有价值，但首版不需要付出额外系统开发复杂度。C# 同样适合服务，尤其 Windows；选择 Go 是为独立、跨平台的小型任务管家，并非 C# 做不到。

## 首版边界

- Go 只调度固定允许的只读 eMAG 巡检入口，不接受任意 shell、用户命令或平台写操作。
- Python 保留采集、数据发布、店铺暂停检查点、同店铺跨进程锁、分析和平台凭证访问。Go 不读取凭证。
- Go 私有持久任务记录：计划、排队、运行、成功、失败、已暂停、需人工核实；按店铺串行，跨店铺有限并行（默认 2，配置有上限）。
- 每次运行持久化唯一任务 ID、计划周期 ID、开始/结束时间和 Python 回执引用；日志有限且不含原始商品或凭证。
- 崩溃重启后，不将旧 running 自动当成功，也不盲目重复执行；先核对工作进程及回执，无法确认则进入需核实。仅明确未启动的排队任务可安全恢复。
- 暂停沿用 Python 的权威控制：停止派发新任务，正在运行任务停在现有安全检查点；Go 不强杀进程冒充已暂停。
- 超时发出协作停止请求并记录；无法确认退出保留运行/待核实并阻止同店铺重入。具体 Windows 协作取消机制在实施时验证。
- 定时到期只补一次，避免电脑休眠恢复后补跑大量过期任务；网络失败按有界退避并尊重平台限制，未知结果不自动重试。
- 先验证独立测试数据、模拟进程、Linux/Windows 编译及重启恢复，再接一项实际只读任务。切换笔记本调度时先备份原任务，确保旧触发器和 Go 只有一方生效，保留回退方案。
- 不同时替换通用 Agent schedules、对话、改价审批或所有现有 Windows 任务。

## 验收

验证同店铺不重入、不同店铺有限并行、暂停与恢复、进程崩溃/管家重启、缺失回执、执行结果未知、休眠错过周期、异常日志上限、固定入口拒绝任意命令，以及不变更现有凭证和快照。

实施顺序：先完成已授权知识库与检查功能并部署；Go 使用独立分支和 PR，避免混在同一变更中。首版上线前验证旧调度与新管家没有重叠。
