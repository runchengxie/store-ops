# 通过外部 Agent 工具开展供货研究

[English](../supplier-research.md)

使用独立安装的 1688 CLI 查找货源候选，保存证据后再人工比较。本阶段 store-ops 不直接调用 CLI，也没有自动结果导入器。任务开始前先阅读[工具配置与职责](external-tools.md)。

1. 确认所需商品、关键规格，以及本次是搜索还是比价。从 eMAG 商品出发时，保留已有店铺、offer ID、SKU 和 PNK；缺失身份保持未知。图片相似不能证明完全同款。
2. 明确外部工具安装位置，记录实际提交、技能声明版本及运行环境。选择 `text_search`、`image_search`、`link_search` 或 `compare` 前，阅读其 `SKILL.md` 和对应的 `references/capabilities/` 文档。使用参考文档中的语法，本文不重复随版本变化的命令参数。
3. 使用外部工具已有授权。授权缺失、CLI 失败或返回 `success: false` 时，说明能力不可用并保留去除凭据后的错误。不编造候选，不擅自以网页或浏览器搜索替代，也不盲目重试结果不确定的操作。
4. 保留返回的结构化 `data`，遵循外部工具要求的展示方式，并将自己的分析与工具输出分开。检查令牌及其他凭据后才保存私有证据，不把原始响应发布进仓库。
5. 为每个候选记录来源链接及商品 ID、供应商身份、精确规格或 SKU、价格与币种、数量阶梯或起订量、带时区的观察时间，以及查询词、图片或链接引用。缺失字段保持未知。API 观察时间与供应商确认的报价有效期应分别记录。
6. 记录规格差异、运费税费或包装是否包含、库存或可供货局限，以及缺失证据。不同数量或规格的报价不能在未说明假设时直接比较。搜索结果不能直接作为到岸成本或供应商的正式报价承诺。
7. 核对标识和规格后，再将候选关联到店铺商品。未核实的关联标记为建议。在现有采购记录中，未确认报价使用参考成本状态；只有另有证据支持时，才能标记供应商已确认或填写实际采购成本。本文不增加 API 或导入数据格式。

在已配置的私有证据位置一并保存任务 ID、工具提交、来源证据和解释。记录哪些内容被手动填入 store-ops，以及对应的记录。采购决策前重新核实价格、规格、数量和可供货情况。本流程不下单、不付款、不修改平台 Listing，也不审批平台写操作。
